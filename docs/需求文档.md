当前基线为 v0.7.1：Windows 采集端、Rust Token sidecar、Node.js 后端、SQLite 存储和实时前端已经跑通软件时长与 AI Token 真实数据闭环；年度点阵图按各图 P95 独立比例分档。白名单及软件元数据由后端 SQLite 持久化，跨浏览器及 `localhost` / `127.0.0.1` 共享。全站网页下拉框已统一为设备选择器样式，Token 面板提供与顶栏双向同步的每日/每周/累计按钮；进程选择支持搜索、滚动和手动添加，清空白名单必须二次确认，总时长与 Token 趋势默认收起。AI Token 已完成 Codex/ZCode 真实验收，DeepSeek Harness 等待真实环境复核。真实硬件传感器采集、开机自启和部分工程化能力尚待完成。

## 四、M1.5 · Token Statistics / AI Token 统计（P1）

### TS-01 · 支持来源

第一版支持 Codex CLI、ZCode 和 DeepSeek Harness。OpenCode 本体、DeepSeek API 直连、DeepSeek 网页/App、费用和账户额度不纳入本阶段。

OpenCode Go 中的 DeepSeek V4 Flash 经 Harness 调用后，按 DeepSeek Harness 来源和实际 provider/model 统计真实 Token；该数据不代表 OpenCode Go 套餐剩余额度。

### TS-02 · 本地来源发现

采集器启动时、每 30 分钟及用户手动触发时扫描本地来源：

- Codex：Simmer 手动路径 → `CODEX_HOME` → `%USERPROFILE%\\.codex`，检查 `sessions` 与 `archived_sessions`。
- DeepSeek Harness：Simmer 手动路径 → `DSH_HOME` → `%USERPROFILE%\\.dsh`，检查 `sessions` 下的 `session.jsonl` 与 `session.jsonl.zstd`。
- ZCode：Simmer 手动路径 → `%USERPROFILE%\\.zcode`，检查 `cli\\db\\db.sqlite` 与 `projects`。

可执行文件仅用于状态诊断，候选包括正在运行的进程、PATH、Windows App Paths、卸载注册表及已知用户目录；禁止递归扫描整个磁盘。

每个来源显示 `ready`、`installed_no_data`、`history_only`、`not_found`、`incompatible` 或 `error`。同一来源默认只启用优先级最高的一个数据根，其他候选仅提示用户选择。

### TS-03 · 解析与采集

- 随采集器打包隐藏式 `simmer-token-scan.exe`，固定使用指定版本的 `tokscale-core`，保留请求级纯数字记录。
- 首次启动导入全部历史；文件变化后延迟约 5 秒增量扫描；每 15 分钟兜底扫描；每日完整校准。
- 增量扫描覆盖最近 48 小时，使用稳定事件 ID 去重；解析失败或 sidecar 超时不得影响软件时长采集。
- Codex 必须处理累计值差分、模型切换、乱序快照、计数回退、分叉会话、归档重复和残缺 JSONL 行。
- ZCode 必须兼容新旧 `model_usage` 字段、未完成记录、缓存/推理重叠和重复扫描。
- DeepSeek Harness 必须兼容普通 JSONL、Zstandard 多帧、残缺尾帧、子任务种子历史和重复消息。

### TS-04 · 统一数据

每个请求级事件只保存：

- `sourceEventId`：稳定哈希。
- `source`：`codex`、`zcode` 或 `dsh`。
- `provider`、`model`、`occurredAt`。
- `inputTokens`：非缓存输入。
- `outputTokens`：非推理输出。
- `cacheReadTokens`、`cacheWriteTokens`、`reasoningTokens`。
- `totalTokens`：以上五类之和。

缓存 Token 和推理 Token 是明细桶，不得在总数中重复计算。

### TS-05 · 隐私与本地安全

严禁上传或持久化提示词、回答、代码、工具参数、项目路径、会话标题、Cookie、API Key、登录信息、`auth.json`、原始日志和原始 usage JSON。

采集器可以在本机读取日志中的必要字段，但服务端只接收规范化数字元数据和来源状态。离线队列保存在 `%APPDATA%\\SimmerCollector`，使用原子写入并自动重试。

### TS-06 · 后端接口与存储

新增 SQLite 表：

- `ai_token_events`：设备、来源、稳定事件 ID、provider、model、时间及 Token 数值。
- `ai_source_status`：设备、来源、状态、路径摘要、错误码和最后检查时间。

`ai_token_events` 使用 `(device_id, source, source_event_id)` 唯一约束，并为时间、来源、provider、model 建立索引。

新增接口：

- `POST /api/ai-token-events`：Bearer 鉴权，批量接收 Token 事件和来源状态。
- `GET /api/ai-tokens/summary`、`trend`、`year`、`breakdown`、`sources`：提供汇总、趋势、年度热力图、排行和来源状态。

现有 `/api/ingest` 软件时长接口和数据库结构保持兼容。

### TS-07 · 前端展示

新增“AI Tokens”面板，包含 Token 分类概览、默认收起且可按需展开的每日/每周/累计趋势、年度 P95 独立比例热力图、来源排行、模型排行，以及设备/来源/provider/model/时间范围筛选。来源、provider、model 使用统一自定义下拉；面板内时间按钮与顶栏双向同步。

未安装、不兼容或没有数据时显示明确状态，不以零值冒充没有使用。`deepseek-v4-flash` 按实际模型名称展示，不冒充 OpenCode Go 套餐配额。

### TS-08 · 验收标准

- 首次运行可以导入 Codex、ZCode 和 DSH 的全部可读历史。
- 重复启动、重复扫描和断网重试不会重复计数。
- 三种来源的 Token 分类与本地源数据一致，缓存和推理不会重复增加总数。
- 找到历史但程序不存在时仍能显示 `history_only` 并继续统计；找到程序但没有历史时显示 `installed_no_data`。
- 不同浏览器访问面板时看到同一份服务器 Token 数据。
- 不读取、存储或上传对话文本及认证信息。
- 现有软件时长、白名单、热力图和采集器功能无回归。

### TS-09 · 明确不做

- OpenCode 独立数据库适配。
- DeepSeek 直连 API 代理或调用方 SDK。
- DeepSeek 网页/App Token 估算。
- 账户额度、订阅周期和费用统计。
- 多个同类安装根目录的自动合并。
- 跨设备原始会话详情同步。

- ✅ **TS-01～TS-07 已实现**：Codex/ZCode/DSH 来源发现、固定版本请求级解析、五类互斥 Token、隐私边界、幂等存储/API 与前端 Token 面板已接通。
- ✅ **Codex / ZCode 真实环境验收**：首次全量扫描识别 Codex 41 个文件和 ZCode 1 个数据库；真实页面可按来源与模型筛选，跨浏览器读取同一份 SQLite 数据。

1. **M1 最小闭环（已完成）**：CAP-01/02/03/05/07 + SRV-01～05 已接入真实数据；CAP-04 仅剩开机自启。

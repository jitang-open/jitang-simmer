## 三、技术方案说明

### 3.1 技术选型

- **零依赖纯前端**：HTML + CSS + 原生 JavaScript，未使用任何框架或第三方图表库，双击 `index.html` 即可运行，无需构建、无需联网。
- **图表全部手写 SVG/DOM**（`js/charts.js`）：点阵图、平滑折线图（Catmull-Rom 曲线 + 渐变面积 + 描边动画）、横向柱状图、环形图、竖向柱状图，统一由全局 tooltip 提供悬浮提示。

### 3.3 核心设计决策

1. **点阵图分档算法**：绝对时长 6 档（`LEVEL_HOURS = [0.5, 1, 2, 4, 6]` 小时，6h+ 顶格，v0.6.3 起）——颜色即强度，轻度使用不满格；此前采用 GitHub 式分位数分档（35%/62%/86%），因"数据少时一天即顶格"而废弃。
2. **假数据的真实性**：模拟了周末/工作日差异、季节波动、偶发"爆肝日"、设备"未开机日"（约 9%），使点阵图呈现真实的使用节律；固定随机种子 `20260820` 保证每次打开数据一致。
3. **白名单即过滤器**：白名单状态存入全局 `state.whitelist`，所有统计查询函数接收软件 id 列表实时过滤，关闭开关即刻从全部统计中剔除。
4. **多设备聚合规则**：时长类指标多设备**求和**，百分比类指标（CPU/内存/温度等）多设备**取平均**，功耗多设备求和。

### 3.4 动效清单

- 点阵格：入场波浪式逐个弹出（按列错位延迟）；悬停弹性放大 + 光晕 + 白描边
- 折线图：描边绘制动画 + 面积淡入；悬停显示垂直参考线 + 数据点 + tooltip
- 横向柱状图：入场宽度生长动画；悬停行高亮、数值变绿
- 环形图：分段悬停加粗 + 光晕；白名单开关：弹性滑动
- 卡片：入场上浮淡入；概览卡悬停上浮 + 绿色描边

## 四、后续接入真实后端的建议

1. **数据采集端**（每台电脑运行）：
   - 软件时长：Windows 可用 `Get-Process` / WMI 轮询前台进程，或调用 Windows API（`GetForegroundWindow`）记录焦点窗口；
   - 硬件指标：LibreHardwareMonitor / HWiNFO 提供 CPU/GPU 温度、功耗、占用率；
   - 建议每分钟聚合一次上报。
2. **接口约定**：只需让后端接口返回与 `js/data.js` 导出函数相同结构的数据（年度逐日分钟数、24 小时分布、逐小时硬件指标），前端图表层无需改动。
3. **上传协议**：每台设备携带 `deviceId` 上报，服务端按设备 + 日期存储，前端「全部设备」视图由服务端聚合或前端聚合均可（当前为前端聚合）。
4. **白名单持久化**：白名单与软件清单元数据均通过 localStorage 持久化（`simmer.whitelist` / `simmer.apps` / `simmer.appsOff` / `simmer.appsRemoved`，v0.6.2 三态模型）；接入后端后建议改为按用户在服务端持久化（SRV-05）。

## 五、如何运行

M1 起系统由三部分组成（详见 README）：

1. **后端**：`cd server && npm install && npm start` → `http://localhost:8788`
2. **采集端**：`cd collector/SimmerCollector && dotnet build -c Release`，运行托盘程序并在设置中填入 Token
3. **面板**：浏览器访问 `http://localhost:8788/index.html`（● 实时数据；后端未连接时自动回退演示数据，直接双击 `index.html` 也可查看演示模式）

1. **点阵图分档重构**：由相对分位数（百分位切档，数据少时一天即顶格）改为**绝对时长分档**，全站总时长与单软件点阵统一阈值——颜色即强度，轻度使用不再满格。阈值经两轮调整定为 `[0.5, 1, 1.5, 2, 2.5, 3, 3.5, 4]` 小时（4h+ 顶格，空 + 8 档）。

### v0.6.2（2026-08-21 21:36:30）· 白名单模型重构：完全用户自主
1. **清单只显示用户接触过的软件**：白名单面板不再罗列全部已观测进程——只有用户主动添加（开启）或添加后关闭的软件出现在面板；从未接触过的新检测进程只出现在「＋添加」的候选下拉中（标"未添加 · 累计 X 分钟"）。
2. **live 模式首次访问为空白名单**：不再自动全选任何进程，面板显示引导文案，由用户从检测到的进程里自主挑选；mock 回退模式仍默认全选演示软件。
3. **三态状态模型**：`whitelist`（开启）/ `offApps`（添加后关闭，留在面板）/ `removedApps`（删除，彻底消失）三个集合分别持久化（`simmer.whitelist` / `simmer.appsOff` / `simmer.appsRemoved`）。删除从三个集合同时剔除，即使存储异常也不会复活。
4. **修正一处误诊**：此前记载"ZCode 内嵌浏览器（IAB）的 localStorage 为会话级、刷新即清"——经复查为**误诊**，真实原因正是 v0.6.1 修复的 `loadWhitelist` 用 mock id 过滤存储名单的 bug（exe 名被滤成空集后又被启动逻辑覆盖为全选，表现为"状态丢失"）。IAB 的 localStorage 实际跨刷新持久（`simmer.apps` 实测保留），此前相关结论作废。
5. 单元测试：7 场景全过（空白名单起点 / 添加后显示 / 关闭留清单 / 删除消失 / 刷新稳定 / 存储丢失不复活 / 新进程不自动出现）。

## 三、技术方案说明

### 3.1 技术选型

- **零依赖纯前端**：HTML + CSS + 原生 JavaScript，未使用任何框架或第三方图表库，双击 `index.html` 即可运行，无需构建、无需联网。
- **图表全部手写 SVG/DOM**（`js/charts.js`）：点阵图、平滑折线图（Catmull-Rom 曲线 + 渐变面积 + 描边动画）、横向柱状图、环形图、竖向柱状图，统一由全局 tooltip 提供悬浮提示。

### 3.2 文件结构

```
pc-usage-dashboard/          # 本地目录名（仓库名为 jitang-simmer）
├── index.html               # 页面结构（侧边栏 + 顶栏 + 六大区块）
├── README.md                # GitHub 仓库说明
├── LICENSE                  # MIT
├── .gitignore
├── css/
│   └── style.css            # GitHub × Spotify 深色主题、全部动效
├── js/
│   ├── data.js              # 假数据层（未来对接真实后端时只需替换此文件）
│   ├── charts.js            # 图表渲染引擎（heatmap / line / hbars / donut / vbars）
│   └── app.js               # 应用主逻辑（状态管理 + 渲染调度）
└── docs/
    └── 交接文档.md           # 本文档
```

### 3.3 核心设计决策

1. **点阵图分档算法**：采用与 GitHub 一致的**分位数分档**（35% / 62% / 86% 分位），而非线性阈值——保证任何数据规模下深绿、浅绿、空格都自然分布，视觉相似度最高。
2. **假数据的真实性**：模拟了周末/工作日差异、季节波动、偶发"爆肝日"、设备"未开机日"（约 9%），使点阵图呈现真实的使用节律；固定随机种子 `20260820` 保证每次打开数据一致。
3. **白名单即过滤器**：白名单状态存入全局 `state.whitelist`，所有统计查询函数接收软件 id 列表实时过滤，关闭开关即刻从全部统计中剔除。
4. **多设备聚合规则**：时长类指标多设备**求和**，百分比类指标（CPU/内存/温度等）多设备**取平均**，功耗多设备求和。

### 3.4 动效清单

- 点阵格：入场波浪式逐个弹出（按列错位延迟）；悬停弹性放大 + 光晕 + 白描边
- 折线图：描边绘制动画 + 面积淡入；悬停显示垂直参考线 + 数据点 + tooltip
- 横向柱状图：入场宽度生长动画；悬停行高亮、数值变绿
- 环形图：分段悬停加粗 + 光晕；白名单开关：弹性滑动
- 卡片：入场上浮淡入；概览卡悬停上浮 + 绿色描边

## 四、后续接入真实后端的建议

1. **数据采集端**（每台电脑运行）：
   - 软件时长：Windows 可用 `Get-Process` / WMI 轮询前台进程，或调用 Windows API（`GetForegroundWindow`）记录焦点窗口；
   - 硬件指标：LibreHardwareMonitor / HWiNFO 提供 CPU/GPU 温度、功耗、占用率；
   - 建议每分钟聚合一次上报。
2. **接口约定**：只需让后端接口返回与 `js/data.js` 导出函数相同结构的数据（年度逐日分钟数、24 小时分布、逐小时硬件指标），前端图表层无需改动。
3. **上传协议**：每台设备携带 `deviceId` 上报，服务端按设备 + 日期存储，前端「全部设备」视图由服务端聚合或前端聚合均可（当前为前端聚合）。
4. **白名单持久化**：v0.3.0 起白名单已通过 localStorage（键 `pulseboard.whitelist`）在本地持久化，刷新/重开页面后保留；接入后端后建议改为按用户在服务端持久化。

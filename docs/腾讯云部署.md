# 腾讯云远程部署

项目已提供面向腾讯云 CVM 的 Docker Compose 部署：Node.js 24 服务端和前端由同一容器提供，Caddy 自动申请 HTTPS 证书；浏览器面板受 Basic Auth 保护，采集端上报接口继续使用独立 Bearer Token。SQLite、证书和 Caddy 状态都保存在 Docker volume 中。

## 1. 准备服务器与域名

1. 建议使用 Ubuntu 22.04/24.04 的腾讯云 CVM，并安装 Docker Engine 与 Compose 插件。
2. 为服务器绑定固定公网 IP，把域名 A 记录指向该 IP。
3. 腾讯云安全组只放行 TCP 22、80、443；不要对公网开放 8788。
4. 把本仓库上传或拉取到服务器。远程服务器只需要 `index.html`、`css/`、`js/`、`server/` 和 `deploy/`。

## 2. 创建部署密钥

在仓库根目录执行：

```bash
cp deploy/.env.example deploy/.env
openssl rand -hex 32
docker run --rm caddy:2.10-alpine caddy hash-password --plaintext '替换成面板强密码'
```

把随机 Token、域名、用户名和 Caddy 输出的完整 bcrypt 哈希写入 `deploy/.env`；bcrypt 哈希请保留示例中的单引号，避免 `$` 被 Compose 当作变量展开。`.env` 含密钥，不应提交到 Git。

## 3. 启动

```bash
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
docker compose --env-file deploy/.env -f deploy/compose.yaml ps
docker compose --env-file deploy/.env -f deploy/compose.yaml logs -f --tail=100
```

DNS 生效后打开 `https://你的域名`，输入面板用户名和密码。采集端设置中的“服务器地址”填写同一个 HTTPS 地址，“Token”填写 `SIMMER_TOKEN`。`/api/ingest` 与 `/api/ai-token-events` 不走 Basic Auth，但仍必须携带高强度 Bearer Token；其他页面和查询接口由 Caddy 保护。

## 4. 更新与备份

更新代码后重新运行 `docker compose ... up -d --build`。数据默认保存在 `simmer_data` volume；升级前可备份：

```bash
docker run --rm -v pc-usage-dashboard_simmer_data:/data -v "$PWD":/backup alpine \
  tar czf /backup/simmer-data-$(date +%F).tar.gz -C /data .
```

不要把 `deploy/.env`、`server/config.json` 或数据库备份放进公开仓库。暂停某台设备时，服务端会确认接收但丢弃暂停期间新上报的软件分钟与 Token 事件，历史记录不会删除。

## 5. 与现有 MinIO 共用服务器（仅开放采集接口）

若 `119.45.179.55` 已由 `/opt/jitang-minio` 中的 Caddy 和 MinIO 占用 80/443，不要再启动本项目自带的 Caddy。使用独立 Compose 文件只运行 Simmer，并接入现有 `jitang-object-storage` 网络：

```bash
sudo install -d -m 0755 /opt/pc-usage-dashboard/data
cd /opt/pc-usage-dashboard
sudo docker compose --env-file deploy/.env -f deploy/compose.tencent-collector.yaml \
  -p pc-usage-dashboard up -d --build
```

此配置只把 8788 绑定到服务器回环地址，同时给容器设置网络别名 `simmer-dashboard`。在 `/opt/jitang-minio/Caddyfile` 的 `119.45.179.55` 站点中，把以下路由放在 MinIO 的兜底 `handle` 之前：

```caddyfile
@simmer_collector {
	method POST
	path /simmer/api/ingest /simmer/api/ai-token-events /simmer/api/hardware-samples /simmer/api/device-heartbeat
}
handle @simmer_collector {
	uri strip_prefix /simmer
	reverse_proxy simmer-dashboard:8788
}
handle {
	reverse_proxy minio:9000
}
```

修改后先验证再热重载，避免影响 MinIO：

```bash
cd /opt/jitang-minio
sudo docker compose exec -T caddy caddy validate --config /etc/caddy/Caddyfile
sudo docker compose exec -T caddy caddy reload --config /etc/caddy/Caddyfile
```

采集器的服务器地址填写 `https://119.45.179.55/simmer`。公网只路由四个带 Bearer Token 的 POST 接口；查询、设备管理和仪表盘仍不可从公网访问。需要查看仪表盘时在本机建立 SSH 隧道：

```powershell
ssh -L 18788:127.0.0.1:8788 腾讯云2
```

然后访问 `http://127.0.0.1:18788`。8788 不需要加入腾讯云安全组。

### 历史数据库迁移与备份

迁移前先让采集器完成最后一次上报并退出，再停止本地 Node 服务。对 SQLite 执行 WAL checkpoint 和完整性检查，只上传 checkpoint 后的 `simmer.db`；云端容器必须在数据库放入数据目录后再启动。上线后可在服务器备份：

```bash
cd /opt/pc-usage-dashboard
sudo docker compose --env-file deploy/.env -f deploy/compose.tencent-collector.yaml \
  -p pc-usage-dashboard stop simmer
sudo tar czf /opt/simmer-data-$(date +%F-%H%M%S).tar.gz -C data .
sudo docker compose --env-file deploy/.env -f deploy/compose.tencent-collector.yaml \
  -p pc-usage-dashboard start simmer
```

回滚时先暂停所有采集器并停止云端 Simmer，把云端最新 `simmer.db` 同步回本机后再恢复本地服务；不要直接启用迁移前的旧数据库，否则会丢失切换后的记录。
